向量检索系统

向量检索（Vector Retrieval / ANN Search）是现代推荐系统召回层的核心基础设施。双塔模型、图神经网络、多兴趣模型等召回算法都需要将物品 Embedding 存储在向量索引中，在线阶段通过近似最近邻搜索（ANN）快速检索与用户向量最相似的物品。本章将系统介绍向量检索的核心算法与工程实践。

17.1 为什么需要 ANN

在推荐系统中，物品库规模通常达到数千万甚至数十亿级别。精确最近邻搜索（KNN）的计算复杂度为 O(N·d)，当 N 达到亿级时，暴力搜索的延迟远超系统预算。因此，工业界采用近似最近邻搜索（ANN）算法，在牺牲少量精度的情况下大幅降低搜索延迟。

17.2 量化方法

17.2.1 乘积量化 (PQ)

PQ [1] 将原始向量空间分解为 M 个子空间的乘积，每个子空间独立进行 K-Means 聚类，得到 M 个码本。原始向量被压缩为 M 个聚类中心的索引（Code），存储开销从 O(N·d) 降低到 O(N·M)。查询时通过查表方式快速计算近似距离。PQ 是 Faiss [2] 中最常用的量化方法之一。

17.2.2 优化乘积量化 (OPQ)

OPQ [3] 在 PQ 基础上引入正交旋转矩阵，使各子空间的方差更加均衡，提升量化质量。

17.3 图基方法

17.3.1 HNSW (Hierarchical Navigable Small World)

HNSW [4] 是当前工业界最主流的 ANN 算法。其核心思想是构建一个层次化的小世界图：上层图稀疏，用于快速导航；下层图密集，用于精确搜索。搜索时从上层开始，逐层向下细化，最终在底层找到最近邻。HNSW 在召回率和延迟方面表现优异，是 Faiss、Milvus [5] 等向量检索库的核心索引类型。

HNSW 的关键参数包括：

  • M：每个节点的最大邻居数，影响图的密度和内存占用
  • efConstruction：构建时的搜索宽度，影响索引质量
  • efSearch：查询时的搜索宽度，影响召回率和延迟

17.4 倒排方法

17.4.1 IVF (Inverted File Index)

IVF 通过 K-Means 聚类将向量空间划分为 nlist 个 Voronoi 单元。查询时只搜索最近的 nprobe 个单元，将搜索范围从 N 缩小到 N×nprobe/nlist。IVF 可以与 PQ 结合（IVF-PQ），同时实现搜索加速和向量压缩。

17.4.2 IVF-HNSW

IVF-HNSW 将 IVF 的聚类中心查找替换为 HNSW 检索，避免了暴力查找最近聚类中心的开销，在大规模数据集上表现优异。

17.5 工业实践

17.5.1 Faiss

Faiss [2] 是 Facebook 开源的向量检索库，支持 IVF、PQ、HNSW 等多种索引类型，以及它们的组合。Faiss 同时支持 CPU 和 GPU，是工业界使用最广泛的向量检索工具之一。

17.5.2 Milvus

Milvus [5] 是 Zilliz 开源的云原生向量数据库，支持十亿级向量检索，提供完善的索引管理、数据增删改查以及分布式部署能力。

17.6 本章小结

本章系统介绍了推荐系统中的向量检索技术。量化方法（PQ、OPQ）通过压缩向量降低存储和计算成本；图基方法（HNSW）在召回率和延迟方面表现最优，是当前工业界的主流选择；倒排方法（IVF）通过聚类筛选缩小搜索范围。工业实践中通常采用 IVF-PQ 或 IVF-HNSW 等组合方案，在亿级向量库上实现毫秒级搜索。
