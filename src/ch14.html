第四部分 推荐系统工程实践 · 第 14 章

特征工程

特征工程是推荐系统的基础环节。尽管深度学习模型具备一定的自动特征交叉能力，但在工业级推荐系统中，高质量的特征工程仍然是决定模型效果上限的关键因素。本章将系统介绍推荐系统中的特征体系，包括用户特征、物品特征、上下文特征以及特征处理技术。

14.1 用户侧特征

14.1.1 基础画像特征

用户基础画像特征通常包括：

  • 人口统计特征：年龄、性别、地域、城市级别等
  • 设备特征：操作系统、机型、App 版本、网络类型等
  • 账号特征：注册时长、新老用户标识、会员等级等
  • 兴趣标签：由用户历史行为聚类或内容偏好模型生成的兴趣 Tag

14.1.2 行为序列特征

用户行为序列是推荐系统中最核心的特征之一。根据时间粒度，通常分为：

  • 短期行为序列：最近 N 次交互的物品列表，用于捕捉用户即时兴趣
  • 长期行为序列：过去数周或数月的交互汇总，用于建模用户稳定偏好
  • 实时行为序列：当前 Session 内的行为，用于捕捉用户瞬时意图

14.1.3 统计特征

用户侧统计特征通过对历史行为进行聚合统计得到，例如：

  • 过去 1/7/30 天的点击数、点赞数、评论数、分享数
  • 各类内容的消费占比（如短视频 vs 直播 vs 图文）
  • 活跃时段分布、平均观看时长、完播率等
  • 转化率、GMV 贡献等商业化指标

14.2 物品侧特征

14.2.1 基础元数据特征

物品基础元数据通常包括：

  • 内容属性：标题、标签、类目、时长、分辨率等
  • 创作者特征：作者 ID、粉丝数、历史表现、账号等级等
  • 发布特征：发布时间、新鲜度、地域限制等
  • 质量特征：清晰度、完播率、互动率等统计指标

14.2.2 内容理解特征

随着大模型技术的发展，基于 LLM 和 VLM 的内容理解特征越来越重要：

  • ASR 文本摘要：由语音识别 + LLM 生成的视频内容摘要
  • 视觉 Embedding：由 VLM 提取的多模态向量表示
  • 主题分类：由大模型自动生成的内容主题标签
  • 评论摘要：由 LLM 对评论区进行情感分析和观点提取

14.3 上下文特征

上下文特征描述推荐请求发生时的环境信息：

  • 时间特征：小时、星期、节假日、季节等
  • 位置特征：GPS 位置、城市、商圈等
  • 场景特征：首页推荐、详情页推荐、搜索推荐等不同场景
  • 请求特征：请求来源、刷新次数、Session 长度等

14.4 特征处理技术

14.4.1 特征离散化

连续特征通常需要离散化为类别特征，常见方法包括：

  • 等宽分桶：将值域均匀划分为 N 个区间
  • 等频分桶：使每个桶内样本数量大致相等
  • 决策树分桶：利用 GBDT 自动学习最优分裂点
  • 对数分桶：对长尾分布特征先取对数再等宽分桶

14.4.2 特征 Embedding

类别特征通常通过 Embedding 层映射为低维稠密向量。对于高基数特征（如 Item ID、User ID），工业界通常采用以下策略：

  • Hash Embedding：对 ID 进行 Hash 映射到固定大小的 Embedding 表，解决词表过大问题
  • 预训练 Embedding：通过 Word2Vec、GNN 等方法离线预训练 Item Embedding，再加载到精排模型中
  • 动态 Embedding：在训练过程中实时更新，适应新物品和新用户的快速变化

14.4.3 特征穿越与防护

特征穿越（Feature Leakage）是指训练时使用了在线推理时无法获取的信息，导致离线指标虚高但线上效果下降。常见的特征穿越类型包括：

  • 时间穿越：使用了请求之后才产生的反馈数据
  • 聚合穿越：统计特征的时间窗口包含了当前请求时间点
  • 标签穿越：特征中直接或间接包含了标签信息

工业界通常通过严格的时间对齐、窗口截断和特征血缘追踪来防止特征穿越。

14.5 本章小结

本章系统介绍了推荐系统中的特征工程体系。用户侧特征包括基础画像、行为序列和统计特征；物品侧特征包括基础元数据和内容理解特征；上下文特征描述推荐请求的环境信息。在特征处理方面，介绍了离散化、Embedding 和特征穿越防护等关键技术。随着大模型技术的发展，基于 LLM/VLM 的内容理解特征正在成为推荐系统特征工程的新方向。
