离线服务

推荐系统的离线服务承担着数据采集、样本构建、特征生成、模型训练以及索引维护等核心功能。离线服务的质量直接决定了在线推荐效果的上限。本章将系统介绍推荐系统离线架构中的关键组件与流程。

15.1 样本拼接

样本拼接是离线架构中最核心的环节。推荐模型的训练样本由特征（Feature）和标签（Label）两部分组成，而这两部分数据通常来源于不同的数据流。

15.1.1 特征流与标签流

在用户每次发起推荐请求时，系统会将用户特征、物品特征及上下文信息打包为 Kafka 消息发送出去，构成特征流。同时，用户与推荐物品发生交互行为后，客户端会将行为日志上报至埋点网关，经 Kafka 写入 Redis，构成标签流。样本拼接服务在固定或动态设定的拼接窗口内（例如 20 分钟），尝试将特征流与标签流进行关联，生成完整的训练样本 (user, item, context, label)。

15.1.2 拼接率优化

样本拼接率是离线架构的重要监控指标。影响拼接率的主要因素包括：请求 ID 一致性、拼接窗口长度、埋点完整性、时钟同步。工业界通常通过双流对齐校验、窗口动态调整和埋点质量监控来提升拼接率。

15.2 特征生成与存储

15.2.1 用户特征存储

用户特征通常分为实时特征和离线特征两部分。实时特征（如最近 N 次行为、当前 Session 信息）通常存储在 Redis 中，支持毫秒级读写；离线特征（如长期兴趣标签、统计特征）通常存储在 HBase 或 Hive 中，按天或小时更新。

15.2.2 物品特征存储

物品特征相对稳定，通常通过离线计算后写入正排索引服务。物品特征更新频率取决于内容属性：静态属性（如类目、标签）在发布时即写入；统计特征（如点击数、点赞数）按小时或天级更新；实时统计特征（如实时热度）通过流式计算实时更新。

15.3 模型训练

15.3.1 批量训练

传统推荐模型通常采用批量训练：每天或每小时收集训练数据，在 GPU 集群上完成一轮完整训练，然后将模型发布到线上。批量训练的优势在于训练稳定、效果可验证，但延迟较大。

15.3.2 流式训练

随着实时推荐需求的增长，越来越多的系统采用流式训练：训练样本以 Kafka 消息流的形式实时产生，模型在线增量更新。流式训练能够将用户行为到模型更新的延迟从天级压缩到分钟级甚至秒级。但面临数据分布漂移、正负样本顺序（延迟反馈问题）、模型稳定性和特征一致性等挑战。

15.3.3 混合训练

工业界通常采用批量训练 + 流式训练的混合方案：每天用批量训练生成 Base 模型，然后在白天通过流式训练进行增量更新，夜间再进行批量全量训练。

15.4 索引构建

15.4.1 正排索引

正排索引以 Item ID 为 Key 存储物品完整特征，用于已知 Item ID 后的快速特征查询。通常以 Redis 或内存数据库为载体。

15.4.2 倒排索引

倒排索引以触发项为 Key，映射到关联物品列表。常见的倒排索引包括：Tag 倒排（兴趣标签→物品列表）、I2I 倒排（物品 ID→相似物品列表）、向量索引（通过 HNSW、IVF 等结构支持 ANN 检索）。

15.5 本章小结

本章系统介绍了推荐系统的离线服务架构。样本拼接服务将特征流与标签流关联生成训练样本。特征存储采用实时与离线分层策略。模型训练从批量训练到流式训练再到混合训练。索引构建包括正排索引和倒排索引两大类。
