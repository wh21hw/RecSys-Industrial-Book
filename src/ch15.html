离线服务

推荐系统的离线服务承担着数据采集、样本构建、特征生成、模型训练以及索引维护等核心功能。离线服务的质量直接决定了在线推荐效果的上限。本章将系统介绍推荐系统离线架构中的关键组件与流程。

15.1 样本拼接

样本拼接是离线架构中最核心的环节。推荐模型的训练样本由特征（Feature）和标签（Label）两部分组成，而这两部分数据通常来源于不同的数据流，需要通过样本拼接服务进行关联。

15.1.1 特征流与标签流

在用户每次发起推荐请求时，系统会将用户特征、物品特征及上下文信息打包为 Kafka 消息发送出去，构成特征流。同时，用户与推荐物品发生交互行为（如点击、点赞、分享等）后，客户端会将行为日志上报至埋点网关，经 Kafka 写入 Redis，构成标签流。

样本拼接服务在固定或动态设定的拼接窗口内（例如 20 分钟），尝试将特征流与标签流进行关联，生成完整的训练样本 (user, item, context, label)。

15.1.2 拼接率优化

样本拼接率是离线架构的重要监控指标。拼接率过低意味着大量用户反馈无法与推荐请求对应，导致训练数据损失。影响拼接率的主要因素包括：

  • 请求 ID 一致性：特征流和标签流必须使用相同的请求 ID 进行关联
  • 拼接窗口长度：窗口过短会导致延迟反馈丢失，过长会增加存储成本
  • 埋点完整性：客户端埋点丢失会直接导致标签流缺失
  • 时钟同步：特征流和标签流的服务器时间差异可能导致关联失败

15.2 特征生成与存储

15.2.1 用户特征存储

用户特征通常分为两类存储方式：

  • 实时特征：存储在 Redis 中，由流式计算服务实时更新，用于捕捉用户即时兴趣变化
  • 离线特征：存储在 Hive/HDFS 中，按天级批量计算，用于长期画像建模

对于用户行为序列，工业界通常采用分层存储策略：

  • 最近 50 条行为存储在 Redis，用于在线实时推荐
  • 最近 500 条行为存储在内存数据库（如 RocksDB），用于粗排和精排
  • 全量历史行为存储在 HDFS，用于离线模型训练

15.2.2 物品特征存储

物品特征通常通过正排索引（Forward Index）进行存储和管理。正排索引以 Item ID 为 Key，存储物品的完整特征信息，包括 Embedding 向量、类别标签、统计特征以及内容属性等。

物品特征的更新策略取决于特征类型：

  • 静态特征（如标题、类目）：发布时写入，基本不变
  • 统计特征（如点赞数、播放数）：准实时更新（分钟级）
  • Embedding 向量：随模型训练周期更新（小时级或天级）

15.3 模型训练

15.3.1 批量训练

传统推荐模型通常采用批量训练（Batch Training）方式：每天从 Hive 中读取前一天的训练样本，在 GPU 集群上完成一轮完整训练，然后将模型发布到线上。批量训练的优势在于训练稳定、效果可验证，但延迟较大，难以捕捉用户兴趣的即时变化。

15.3.2 流式训练

随着实时推荐需求的增长，越来越多的系统采用流式训练（Streaming Training）：训练样本以 Kafka 消息流的形式实时产生，模型在线增量更新。流式训练能够将用户行为到模型更新的延迟从天级压缩到分钟级甚至秒级。

流式训练面临的核心挑战包括：

  • 数据分布漂移：实时数据分布可能与历史分布不一致
  • 正负样本顺序：正样本通常比负样本先到达（延迟反馈问题）
  • 模型稳定性：增量更新可能导致模型震荡
  • 特征一致性：在线特征与离线特征的口径必须严格对齐

15.3.3 混合训练

工业界通常采用批量训练 + 流式训练的混合方案：每天用批量训练生成 Base 模型，然后在白天通过流式训练进行增量更新，夜间再进行批量全量训练。这种方案兼顾了训练稳定性和实时性。

15.4 索引构建

索引构建是离线服务到在线服务的桥梁。推荐系统中的索引主要分为两类：

15.4.1 正排索引

正排索引以 Item ID 为 Key 存储物品完整特征，用于已知 Item ID 后的快速特征查询。通常以 Redis 或内存数据库为载体，支持毫秒级查询。

15.4.2 倒排索引

倒排索引以触发项（Tag、类目、Embedding 等）为 Key，映射到关联物品列表。常见的倒排索引包括：

  • Tag 倒排：兴趣标签 → 物品列表
  • I2I 倒排：物品 ID → 相似物品列表（用于 ItemCF 召回）
  • 向量索引：通过 HNSW、IVF 等结构支持 ANN 检索

15.5 本章小结

本章系统介绍了推荐系统的离线服务架构。样本拼接服务将特征流与标签流关联生成训练样本，拼接率是核心监控指标。特征存储采用实时与离线分层策略，兼顾低延迟与大规模。模型训练从批量训练到流式训练再到混合训练，体现了实时性需求的不断增长。索引构建作为离线到在线的桥梁，包括正排索引和倒排索引两大类。
