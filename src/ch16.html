在线服务

推荐系统的在线服务直接面向用户请求，需要在数十毫秒内完成从召回、排序到结果返回的全流程。在线服务的性能和稳定性直接决定了用户体验。本章将介绍推荐系统在线架构中的核心组件与关键技术。

16.1 推荐请求链路

一次完整的推荐请求链路通常包括以下步骤：

  1. 客户端发起请求：用户打开 App 或刷新页面，客户端向服务端发起推荐请求
  2. 服务端转发：服务端通过推荐 Router 调用推荐系统
  3. 召回：多路召回并行执行，从海量物品库中筛选数千个候选
  4. 粗排：轻量级模型快速筛选至数百个候选
  5. 精排：复杂模型精细排序至数十个候选
  6. 重排：序列级优化，多样性打散
  7. 混排：多业务融合，流量调控
  8. 结果返回：经 Router 返回给服务端，最终下发到客户端

整个链路的端到端延迟通常控制在 200-500ms 以内，其中推荐系统内部耗时通常在 50-100ms。

16.2 模型推理服务

16.2.1 推理引擎

推荐模型的在线推理通常使用以下引擎：

  • TensorFlow Serving：Google 开源的模型服务框架，支持 TF SavedModel 格式
  • TensorRT：NVIDIA 的推理加速引擎，通过算子融合、量化等优化大幅降低推理延迟
  • ONNX Runtime：跨框架推理引擎，支持 PyTorch、TF 等多种模型格式
  • 自研推理框架：大型互联网公司通常自研推理引擎以适配业务需求

16.2.2 模型加速技术

工业界常用的模型加速技术包括：

  • 算子融合（Operator Fusion）：将多个连续算子合并为一个，减少内存访问开销
  • 模型量化（Quantization）：将 FP32 权重压缩为 INT8 或 FP16，减少显存占用和计算延迟
  • 模型蒸馏（Distillation）：用大模型训练小模型，在保持效果的同时降低推理成本
  • 并行推理：对多路召回或多个模型塔并行执行，减少串行延迟
  • 缓存优化：对用户向量等中间结果进行缓存，避免重复计算

16.3 特征服务

在线特征服务负责在推荐请求到达时，实时获取用户和物品的特征信息。工业界通常采用以下架构：

16.3.1 特征服务架构

  • 用户特征服务：从 Redis 或内存数据库读取用户画像、行为序列等特征
  • 物品特征服务：通过正排索引服务，根据 Item ID 批量获取物品特征
  • 实时特征计算：部分特征需要在线实时计算（如"最近 5 分钟点击数"）

16.3.2 特征缓存

为了降低特征获取延迟，工业界通常采用多级缓存策略：

  • 本地缓存：使用 LRU Cache 缓存热点用户/物品特征，命中率高时延迟 <1ms
  • Redis 缓存：作为二级缓存，覆盖更广的特征集合
  • 持久化存储：HBase 或 RocksDB，作为兜底数据源

16.4 降级与容灾

推荐系统需要应对流量高峰、资源受限以及异常故障等场景，通常设计多层降级机制：

16.4.1 降级层次

  • 特征降级：当特征服务异常时，使用默认特征或缓存特征替代
  • 模型降级：当精排模型超时或异常时，回退到粗排结果或更简单的模型
  • 召回降级：当部分召回源异常时，使用其他召回源或缓存结果补充
  • 热榜兜底：当推荐系统完全不可用时，返回全站热门内容作为兜底

16.4.2 DCAF 动态算力分配

DCAF（Dynamic Computation Allocation Framework）是阿里巴巴提出的动态算力分配框架。它将资源分配建模为带约束的背包问题，根据请求价值和算力预算动态选择最优的推理策略：

max Σᵢⱼ xᵢⱼ Qᵢⱼ,   s.t. Σᵢⱼ xᵢⱼ qⱼ ≤ C

通过拉格朗日对偶分析，最优策略简化为选择使 Qᵢⱼ - λqⱼ 最大的动作，其中 λ 通过二分搜索求解。DCAF 实现了"按请求价值进行差异化降级"，在业务收益与系统成本之间取得更优平衡。

16.5 监控与告警

推荐系统在线服务需要完善的监控体系，覆盖以下维度：

  • 服务层监控：QPS、P50/P99 延迟、错误率、GPU 利用率
  • 数据层监控：特征缺失率、特征分布漂移、索引更新延迟
  • 模型层监控：pxtr 均值与分布、PCOC 校准指标、AUC 异常
  • 业务层监控：各业务流量占比、多样性指标、冷启动曝光率
  • 降级监控：降级触发次数、降级流量占比、兜底内容占比

16.6 本章小结

本章系统介绍了推荐系统的在线服务架构。推荐请求链路从客户端到结果返回需要在数百毫秒内完成全流程。模型推理服务通过算子融合、量化、蒸馏等加速技术降低延迟。特征服务采用多级缓存策略保证低延迟获取。降级与容灾机制通过多层降级保障服务连续性。监控体系覆盖服务、数据、模型、业务和降级五个维度，是推荐系统稳定运行的重要保障。
