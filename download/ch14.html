特征工程

特征工程是推荐系统的基石。在工业实践中，特征工程的质量往往比模型选择更决定推荐效果的上限。一个好的特征工程可以让简单模型发挥出色效果，而糟糕的特征工程会让最先进的模型也无能为力。本章将系统介绍推荐系统特征工程的全貌——从特征分类、特征提取、特征处理到自动化特征工程。

14.1 特征分类体系

14.1.1 用户特征

用户特征描述用户的属性和行为偏好，是推荐系统最重要的特征类别之一。

静态属性特征：

  • 人口统计学特征：性别、年龄段、地域、职业、收入水平
  • 设备特征：操作系统、设备型号、网络类型、运营商
  • 注册特征：注册时间、会员等级、实名认证状态

行为统计特征：

  • 活跃度特征：近 7/30 天登录天数、日均使用时长、活跃时段分布
  • 消费特征：历史购买次数、客单价、复购率、最近购买时间
  • 偏好特征：品类偏好分布、价格偏好、品牌偏好、风格偏好

序列行为特征：

  • 短期行为序列：最近 N 次点击/购买/浏览的物品 ID 序列
  • 长期行为序列：最近 30/90 天的行为序列（通常压缩后使用）
  • 负反馈序列：最近忽略/不感兴趣/举报的物品序列

社交关系特征：

  • 社交网络特征：好友数量、社交活跃度、社交影响力（PageRank）
  • 群体特征：所属社区、兴趣圈子、参考群体偏好

14.1.2 物品特征

物品特征描述物品的属性、质量和热度。

基础属性特征：

  • 标识特征：物品 ID、店铺 ID、品牌 ID、类目 ID
  • 属性特征：价格、颜色、尺寸、材质、产地
  • 时间特征：上架时间、库存状态、促销状态

质量统计特征：

  • 热度特征：近 7/30 天点击量、购买量、收藏量、分享量
  • 评分特征：平均评分、评分分布、评价数量
  • 转化特征：点击转化率、加购转化率、退货率

内容特征：

  • 文本特征：标题、描述、评论的 embedding（BERT/LLM 编码）
  • 图像特征：主图、详情图的 embedding（CNN/CLIP 编码）
  • 视频特征：封面图 embedding、视频内容 embedding

14.1.3 上下文特征

上下文特征描述推荐发生时的环境信息。

时间上下文：请求时间（小时/星期/季节）、是否节假日、是否促销期、距上次请求间隔。

空间上下文：用户地理位置、城市级别、天气、温度。

场景上下文：请求来源（首页/搜索/详情页）、页面位置、推荐场景（信息流/详情推荐/购物车推荐）。

设备上下文：屏幕尺寸、网络状况、电量水平。

14.1.4 交叉特征

交叉特征捕获用户与物品、用户与上下文之间的交互模式。

用户-物品交叉：用户对该类目的偏好得分、用户对该品牌的偏好得分、用户历史与该物品的交互次数。

用户-上下文交叉：用户在该时段的活跃度、用户在该地域的购买偏好、用户在该场景的点击偏好。

物品-上下文交叉：物品在该时段的点击率、物品在该地域的销量、物品在该场景的转化率。

三阶交叉：用户-物品-上下文三阶交叉特征（如"该用户在该时段对该类目的点击率"），通常通过模型自动学习而非人工构造。

14.2 统计特征

14.2.1 点击率特征

点击率（CTR）是推荐系统最核心的统计特征。但直接使用全局 CTR 存在以下问题：

（1）冷启动问题：新物品没有历史点击数据，CTR 估计为 0 或不可靠。

（2）位置偏差：高位置曝光的物品 CTR 天然偏低，直接比较不公平。

14.2.2 转化率特征

转化率（CVR）特征比 CTR 更稀疏，因为购买行为远少于点击。CVR 特征的挑战：

数据稀疏：大部分物品的购买次数很少，CVR 估计不可靠。解决方案：使用更长的统计窗口（30 天 vs 7 天）、更强的平滑（更大的 α）。

延迟反馈：用户可能点击后几天才购买，实时 CVR 不准确。解决方案：使用延迟反馈模型（Delayed Feedback Model, DFEM）估计真实 CVR。

多目标统计：除了购买 CVR，还可以统计加购率、收藏率、分享率、评论率等多个目标。这些统计特征为多目标排序模型提供输入。

14.2.3 用户行为统计特征

用户侧的统计特征描述用户的行为模式和偏好：

活跃度分桶：将用户按活跃度分为高/中/低/沉默用户。不同活跃度的用户推荐策略不同——高活用户重多样性，低活用户重热门推荐。

消费能力分桶：按客单价和购买频次将用户分为高/中/低消费用户。影响价格特征和商品推荐策略。

品类偏好向量：统计用户在各类目的点击/购买分布，形成偏好向量。用于召回策略选择和推荐多样性控制。

行为周期性特征：统计用户的活跃时段分布（一天内何时活跃）、活跃周期（每周哪几天活跃）。用于时段推荐和推送时间优化。

14.3 序列特征

14.3.1 行为序列构建

用户行为序列是推荐系统最重要的特征之一，直接决定了序列模型（DIN/DIEN/SIM）的效果。

序列类型：

  • 点击序列：用户最近点击的物品 ID 列表
  • 购买序列：用户最近购买的物品 ID 列表
  • 浏览序列：用户最近浏览（停留 > N 秒）的物品 ID 列表
  • 混合序列：点击+购买+浏览的混合行为序列，行为类型作为 side feature

序列长度选择：短期序列通常 50-200，长期序列可达 1000-5000。DIN 通常用 50-100，SIM 可以处理 1000+ 的长序列。

序列方向：按时间倒序排列（最近的在前）或正序排列。倒序更符合"最近行为最重要"的直觉，且方便截断。

14.3.2 序列编码

行为序列中的每个物品需要编码为向量表示：

ID Embedding：物品 ID 通过 embedding 表映射为向量。这是最基础的编码方式，但冷启动物品没有 embedding。

属性 Embedding：物品的类目、品牌、价格等属性分别 embedding 后拼接。属性 embedding 可以跨物品共享，缓解冷启动。

内容 Embedding：使用预训练模型（BERT/CLIP）编码物品文本/图片，作为物品表示。内容 embedding 对冷启动友好。

位置编码：在序列中加入位置 embedding，表示行为的时间顺序。位置编码可以是绝对位置（第 1/2/3 个）或相对位置（距当前请求的时间间隔）。

行为类型编码：在混合序列中，使用行为类型 embedding（点击/购买/浏览）区分不同行为。购买行为的权重通常高于点击。

14.3.3 长序列处理

长序列（1000+）可以捕获用户长期偏好，但计算开销大。工业实践中的处理策略：

SIM（Search-based Interest Model）方案：不直接处理全序列，而是以目标物品为 query 检索序列中最相关的 K 个行为。检索方式可以是内积检索或学习检索。SIM 可以将 1000+ 序列压缩到 50-100 的相关子序列。

层次化序列：将长序列分层处理——长期序列粗粒度编码（类目级），短期序列细粒度编码（物品级）。长期偏好用类目分布表示，短期兴趣用物品序列表示。

序列摘要：将长序列压缩为固定长度的摘要向量。可以使用平均池化、注意力池化或 RNN 编码。摘要向量作为用户长期偏好的紧凑表示。

时间分桶序列：将长序列按时间分桶（如近 1 天/7 天/30 天/90 天），每个桶内分别编码。不同时间桶的权重不同，近期桶权重更高。

14.4 Embedding 特征

14.4.1 ID Embedding

ID Embedding 是推荐系统最基础也是最重要的特征表示方式。每个物品 ID 和用户 ID 对应一个可学习的稠密向量。

Embedding 维度选择：通常 32-128 维。维度过高容易过拟合且内存占用大，维度过低表达能力不足。实践中，高频物品可以用更高维度，低频物品用更低维度（通过维度共享或哈希）。

Embedding 共享：相关 ID 可以共享 embedding 空间。例如，同一品牌的物品共享品牌 embedding，同一类目的物品共享类目 embedding。共享可以减少参数量和冷启动问题。

哈希 Embedding：对于极大规模 ID（亿级），使用哈希将 ID 映射到固定大小的 embedding 表。虽然存在哈希冲突，但在大规模场景中是可接受的折中。

14.4.2 内容 Embedding

内容 Embedding 使用预训练模型编码物品的多模态内容：

文本 Embedding：使用 BERT/LLM 编码物品标题和描述。取 [CLS] token 或平均 pooling 作为文本表示。文本 embedding 对冷启动物品尤其重要。

图像 Embedding：使用 CNN（ResNet/EfficientNet）或 CLIP 编码物品主图。图像 embedding 捕获视觉相似性，在服饰、家居等视觉导向品类中效果显著。

视频 Embedding：使用 3D-CNN 或 VideoBERT 编码视频内容。封面图 embedding + 视频内容 embedding 组合使用。

融合策略：多模态 embedding 可以拼接、加权融合或通过注意力机制融合。实践中，拼接 + MLP 是最简单有效的方式。

14.4.3 预训练 Embedding

预训练 Embedding 在推荐系统中的应用越来越广泛：

图预训练 Embedding：在用户-物品二部图上预训练图卷积模型（PinSage/GraphSAGE），获得用户和物品的图表示。图 embedding 捕获协同信号和图结构信息。

序列预训练 Embedding：在用户行为序列上预训练序列模型（BERT4Rec/SASRec），获得用户兴趣表示和物品上下文表示。

多模态预训练 Embedding：使用 CLIP 等多模态预训练模型，获得图文对齐的 embedding。CLIP embedding 在跨模态召回中效果优异。

LLM Embedding：使用大语言模型的 embedding 层编码物品文本，获得蕴含丰富世界知识的表示。LLM embedding 可以作为推荐模型的辅助特征。

14.5 特征处理

14.5.1 归一化

不同特征的取值范围差异很大（价格 0-10000，CTR 0-1），需要归一化到统一范围：

Min-Max 归一化：x' = (x - min) / (max - min)，映射到 [0, 1]。简单但受异常值影响。

Z-Score 归一化：x' = (x - μ) / σ，均值为 0 方差为 1。适合近似正态分布的特征。

Log 归一化：x' = log(1 + x)，适合长尾分布的特征（如价格、播放量）。

分桶归一化：将连续值分桶后离散化。例如，价格分为 [0-50, 50-200, 200-500, 500+]。分桶可以捕获非线性关系，但桶的边界选择需要经验。

14.5.2 离散化

连续特征离散化是推荐系统特征处理的常用手段：

等频分桶：每个桶包含相同数量的样本，保证每个桶的统计可靠性。

等距分桶：每个桶的取值范围相同，简单但可能某些桶样本极少。

决策树分桶：使用决策树学习最优分桶边界，使分桶后特征与标签的相关性最强。

Embedding 化：将离散化后的桶 ID 通过 embedding 表映射为向量。这是推荐系统处理离散特征的标准方式。

14.5.3 缺失值处理

特征缺失在推荐系统中很常见——新用户没有历史特征，新物品没有统计特征。处理方式：

默认值填充：使用默认值（0、均值、中位数）填充缺失值。简单但可能引入偏差。

Embedding 缺失：为缺失特征学习一个特殊的"缺失 embedding"，让模型学习如何处理缺失情况。

指示特征：添加二值指示特征标记某特征是否缺失，让模型显式知道哪些特征是缺失的。

基于相似性填充：使用相似用户/物品的特征值填充。例如，用同类目物品的平均 CTR 填充新物品的 CTR。

14.5.4 特征穿越问题

特征穿越（Feature Leakage）是推荐系统中的常见陷阱——训练时使用了线上不可获得的特征，导致离线指标虚高但线上效果差。

时间穿越：使用未来信息作为特征。例如，使用当天全天的 CTR 作为特征训练，但线上推理时只有到当前时刻为止的 CTR。

标签穿越：使用与标签直接相关的特征。例如，使用"是否购买"作为特征预测"是否购买"，形成循环。

聚合穿越：使用包含当前样本的聚合统计特征。例如，物品 CTR 统计包含了当前用户的点击，造成信息泄漏。

防范措施：

  • 严格按时间切分训练/测试集
  • 统计特征只使用历史数据，不包含当前样本
  • 使用在线特征服务模拟线上推理环境
  • Code review 检查特征定义

14.6 自动化特征工程

14.6.1 自动特征生成

人工特征工程耗时且依赖经验，自动化特征工程旨在减少人工干预：

自动交叉：使用模型自动学习特征交叉。DeepFM 的 FM 组件、xDeepFM 的 CIN 组件、AutoInt 的注意力交叉都是自动学习特征交叉的方式。

自动分桶：使用可学习分桶（如 DICE 模型）替代人工分桶。模型自动学习最优分桶边界和每个桶的 embedding。

自动特征选择：使用 L1 正则化、树模型特征重要性或神经架构搜索（NAS）自动选择有效特征。

自动特征生成：使用 AutoFeat 等工具自动生成二阶、三阶交叉特征，然后通过特征选择保留有效组合。

14.6.2 特征监控

特征监控是推荐系统稳定运行的保障：

特征覆盖率监控：每个特征的非空比例。覆盖率突降可能表示数据管道故障。

特征分布监控：特征值的分布变化。分布漂移可能表示用户行为或数据管道变化，需要及时更新模型。

特征重要性监控：特征对模型预测的贡献度变化。重要性突降可能表示特征失效，需要排查原因。

特征相关性监控：特征间的相关性变化。高相关特征的冗余可能影响模型稳定性。

14.7 工业实践

14.7.1 淘宝特征体系

淘宝推荐系统的特征体系是工业级标杆，包含数百个特征：

用户特征层：基础属性（性别/年龄/地域）+ 活跃度统计 + 消费偏好 + 行为序列（短期 50 + 长期 500）。

物品特征层：基础属性 + 质量统计（CTR/CVR/退货率）+ 内容 embedding（BERT 文本 + CLIP 图像）。

交叉特征层：用户-类目偏好 + 用户-品牌偏好 + 用户-价格偏好 + 物品-时段 CTR。

实时特征层：用户最近 5 分钟/1 小时的行为序列和统计，通过实时特征服务提供。

14.7.2 抖音特征体系

抖音推荐系统的特征体系以多模态和实时性为特色：

视频特征：封面图 CLIP embedding + 视频内容 embedding + 音频特征 + 标签特征。

用户实时行为：最近 5 分钟的观看序列、完播率、互动行为。实时特征对短视频推荐至关重要。

上下文特征：时段、网络、设备、前后视频上下文。短视频的上下文依赖性强。

14.8 前沿特征技术

14.8.1 LLM 生成特征

2024-2025 年的最新趋势是使用大语言模型（LLM）生成推荐特征。LLM 的强大语义理解和推理能力可以生成传统方法难以获得的特征：

LLM 内容理解特征：使用 LLM 对物品进行深度内容理解，生成丰富的语义特征。例如，用 GPT-4/Qwen 分析商品描述，生成"风格标签"（如"ins风""日系""复古"）、"适用场景"（如"夏季户外""通勤"）、"目标人群"（如"年轻女性""中年男性"）等。这些特征比人工标签更丰富、更准确。

LLM 用户画像特征：使用 LLM 分析用户的历史行为和评论，生成用户画像摘要。例如，"该用户偏好高性价比的科技产品，关注产品评测，购买决策理性"——这种自然语言画像可以编码为特征供推荐模型使用。

LLM 推理特征：使用 LLM 进行常识推理，生成物品间的关联特征。例如，LLM 推理出"防晒霜"与"夏季户外""海边度假"的关联，生成场景关联特征。这种推理特征突破了协同过滤的局限——即使两个物品没有共同用户，LLM 也能推理出它们的语义关联。

LLM Embedding 特征：使用 LLM 的 embedding 层编码物品文本，获得蕴含世界知识的表示。相比 BERT/Word2Vec，LLM embedding 包含更丰富的语义信息。工业实践中，LLM embedding 通常作为辅助特征，与传统 ID Embedding 拼接使用。

14.8.2 多模态融合特征

随着 CLIP、BLIP-2、LLaVA 等多模态大模型的发展，多模态特征在推荐系统中的应用越来越深入：

CLIP 视觉-文本对齐特征：使用 CLIP 将物品图片和文本编码到同一向量空间。这使得跨模态检索成为可能——用户搜索"红色连衣裙"时，可以通过文本 embedding 直接检索视觉上匹配的物品。

VLM 深度内容理解：使用视觉语言模型（VLM）对视频/图片进行深度理解，生成内容质量评分、美学评分、内容标签等特征。例如，用 Qwen-VL 评估短视频的"内容质量""节奏""吸引力"，生成质量特征用于推荐排序。

多模态行为表示：将用户行为中的物品用多模态 embedding 表示（视觉+文本+音频），而非仅用 ID Embedding。这种多模态行为表示能更准确地捕获用户的兴趣偏好——两个视觉上相似的视频即使没有共同用户，也能通过多模态 embedding 关联起来。

14.8.3 图结构特征

图神经网络（GNN）的发展为推荐系统特征工程带来了图结构特征：

用户-物品图特征：在用户-物品二部图上运行 GNN（如 PinSage、LightGCN），生成用户和物品的图 embedding。图 embedding 捕获了高阶协同信号——不仅考虑直接交互，还考虑二跳、三跳邻居的关系。

物品-物品图特征：构建物品-物品相似图（基于共现、内容相似度等），运行 GNN 生成物品的图表示。图表示能捕获物品间的隐含相似性。

知识图谱特征：将物品属性（类目、品牌、标签）构建为知识图谱，使用 GNN 生成知识增强的物品表示。知识图谱特征对冷启动尤其有效——新物品通过其属性在知识图谱中的位置获得表示。

14.8.4 实时流式特征

随着实时计算技术的发展，流式特征在推荐系统中的重要性越来越高：

实时行为序列：用户最近 5 分钟/1 小时的行为序列，通过 Flink/PSM 等流处理引擎实时计算。实时序列能捕获用户的即时兴趣变化——例如用户刚搜索了"手机壳"，后续推荐应立即反映这一兴趣。

实时统计特征：物品最近 1 小时的 CTR/CVR、用户最近 10 分钟的点击率等。实时统计特征能快速反映物品热度和用户活跃度的变化。

实时趋势特征：基于实时流量数据计算的趋势特征，如"最近 1 小时类目 CTR 变化率""热门搜索词实时排名"。趋势特征帮助推荐系统快速响应热点事件。

流批一体：现代推荐系统采用流批一体的特征计算架构——同一套特征定义既可以在批处理（Spark）上离线计算，也可以在流处理（Flink）上实时计算。流批一体保证了离线训练和在线推理的特征一致性。

14.8.5 用户意图特征

用户意图是推荐系统最核心的信号之一，最新的意图特征技术包括：

意图识别模型：使用序列模型（如 Transformer）对用户最近行为序列进行编码，识别用户的当前意图（如"购物""比价""闲逛"）。意图特征作为推荐模型的上下文输入，帮助模型根据不同意图调整推荐策略。

Session 级意图：将用户一次浏览 Session 中的行为序列编码为 Session 意图向量。Session 意图能捕获用户的即时需求——例如用户在 Session 中连续浏览了多个运动鞋，Session 意图向量会反映"运动鞋购物"意图。

LLM 意图推理：使用 LLM 对用户行为进行意图推理。例如，将用户最近 10 次行为编码为自然语言 prompt，输入 LLM 推理出用户意图："该用户正在寻找夏季运动装备，偏好性价比高的国产品牌"。LLM 意图推理能捕获传统模型难以理解的复杂意图。

14.8.6 特征 Scaling Up

随着推荐系统规模的增长，特征工程也面临 Scaling Up 挑战：

特征数量 Scaling：现代推荐系统包含数千甚至数万个特征。大规模特征管理需要特征平台（Feature Store）——统一管理特征定义、特征计算、特征服务和特征监控。Facebook 的 FBLearner、Uber 的 Michelangelo 都是工业级特征平台。

特征维度 Scaling：Embedding 特征的维度从 32 维增长到 256 维甚至更高。高维 Embedding 提供更强的表达能力，但也带来更大的存储和计算开销。混合维度策略——高频特征用高维，低频特征用低维——是工业实践中的常见方案。

特征更新频率 Scaling：从天级更新到小时级再到秒级更新。更高频率的特征更新能更快反映数据变化，但也对特征管道的稳定性和延迟提出更高要求。

特征一致性 Scaling：随着特征数量和更新频率的增长，保证训练-推理特征一致性越来越困难。现代特征平台通过特征版本管理和在线特征模拟解决这一问题。

14.9 本章小结

特征工程是推荐系统的基石，其质量直接决定推荐效果的上限。本章系统介绍了推荐系统特征工程的全貌——特征分类（用户/物品/上下文/交叉）、统计特征（CTR/CVR 平滑与时间衰减）、序列特征（行为序列构建与长序列处理）、Embedding 特征（ID/内容/预训练）、特征处理（归一化/离散化/缺失值/穿越防范）、自动化特征工程和前沿特征技术。

在前沿特征方面，LLM 生成特征（内容理解/用户画像/推理特征/Embedding）、多模态融合特征（CLIP/VLM/多模态行为表示）、图结构特征（GNN/知识图谱）、实时流式特征（实时序列/统计/趋势）和用户意图特征（意图识别/Session意图/LLM推理）代表了推荐系统特征工程的最新发展方向。

在工业实践中，特征工程的核心原则是：先特征后模型。在模型复杂度达到一定程度后，增加特征的效果远超增加模型参数。特征工程需要持续迭代——监控特征效果、淘汰失效特征、添加新特征，形成闭环优化。

随着 LLM 和多模态大模型技术的发展，自动化特征工程正在减少人工依赖。LLM 生成特征和 VLM 内容理解特征正在成为推荐系统特征工程的新标配。但好的特征工程仍然需要对业务和数据的深入理解——这是算法工程师不可替代的价值。
