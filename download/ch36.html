LLM 与 Agent 推荐

大语言模型（LLM）的推理能力和工具调用能力催生了 Agent（智能体）范式的兴起。Agent 推荐系统将推荐从被动响应转变为主动交互——Agent 可以通过多轮对话理解用户需求，调用多种工具（召回模型、排序模型、知识库、搜索引擎）完成推荐任务，并根据用户反馈调整策略。本章将系统介绍 LLM Agent 在推荐系统中的应用，包括 Agent 架构、工具调用、检索增强生成（RAG）和对话推荐。

36.1 Agent 推荐范式

36.1.1 从被动响应到主动交互

传统推荐系统是"被动响应"式的——用户打开应用，系统基于用户历史行为推荐物品。用户与系统的交互方式有限（点击、滑动、忽略），系统难以深入理解用户的即时需求和偏好变化。

Agent 推荐系统将推荐过程转变为"主动交互"式：

主动询问：Agent 可以主动询问用户需求——"您是想找夏季穿搭还是运动装备？"

澄清式对话：当用户需求模糊时，Agent 通过多轮对话逐步澄清——"您说想要'好看的衣服'，是偏向休闲风还是正式风？"

偏好修正：用户可以实时修正推荐方向——"不要红色的，有没有蓝色款？"Agent 立即调整推荐策略。

解释与教育：Agent 可以解释推荐理由并提供专业建议——"推荐这款防晒霜是因为它的 SPF50+ 适合您提到的户外运动场景，同时质地轻薄适合夏季使用。"

这种主动交互模式使推荐系统从"黑盒推荐"进化为"透明对话"，显著提升了用户体验和推荐准确性。

36.1.2 Agent 架构

推荐 Agent 的典型架构包括以下核心组件：

（1）感知模块（Perception）。接收用户输入（文本、语音、图片），理解用户当前状态和需求。包括意图识别、情绪感知、上下文理解。

（2）规划模块（Planning）。将用户需求分解为可执行的子任务。例如，"帮我搭配一套夏季面试穿搭"分解为：① 确定面试场景和风格偏好 → ② 检索上装 → ③ 检索下装 → ④ 检索鞋子 → ⑤ 检查搭配协调性 → ⑥ 生成推荐列表。

（3）记忆模块（Memory）。维护用户长期偏好（长期记忆）和当前对话上下文（短期记忆）。长期记忆存储用户画像、历史交互、偏好模式；短期记忆维护当前对话的状态和已推荐物品。

（4）工具模块（Tools）。Agent 可以调用的推荐工具集——召回模型、排序模型、知识库查询、搜索引擎、多模态理解模型等。工具模块是 Agent 与传统推荐系统交互的接口。

（5）执行模块（Execution）。根据规划调用工具，整合工具返回结果，生成推荐列表和推荐理由。

（6）反思模块（Reflection）。评估推荐效果，根据用户反馈调整策略。如果用户拒绝了推荐，反思模块分析原因并调整后续推荐方向。

36.2 工具调用推荐

36.2.1 Function Calling 机制

Function Calling 是 LLM Agent 的核心能力——LLM 可以根据用户需求决定调用哪个工具、传入什么参数、如何使用返回结果。在推荐场景中，Function Calling 使 LLM 能够调用传统推荐模型作为工具：

推荐工具函数示例：

// 向量召回工具
recall_items(user_id, query_text, top_k) → item_list

// 精排工具
rank_items(user_id, item_list) → ranked_list

// 知识查询工具
query_knowledge(item_id) → item_attributes

// 搭配推荐工具
get_matching_items(item_id, matching_type) → matched_items

// 多模态理解工具
understand_image(image_url) → text_description

LLM 根据用户输入决定调用哪些工具。例如，用户说"帮我找适合面试的衬衫"，LLM 的调用链可能是：

① 调用 recall_items(user_id, "面试 衬衫", top_k=50) 获取候选集

② 调用 rank_items(user_id, item_list) 精排

③ 调用 get_matching_items(top_item, "裤子") 获取搭配裤子

④ 整合结果生成推荐列表和搭配建议

36.2.2 多工具编排

复杂推荐需求需要编排多个工具协同完成。Agent 需要决定工具调用的顺序、依赖关系和并行策略：

串行调用：工具 B 的输入依赖工具 A 的输出。例如，先召回再排序——rank_items(recall_items(...))。

并行调用：多个独立工具可以并行执行。例如，同时调用文本召回和多模态召回，然后融合结果。

条件调用：根据前序工具的返回决定是否调用后续工具。例如，如果召回结果为空，调用搜索引擎作为兜底。

迭代调用：根据评估结果决定是否重新调用工具。例如，如果推荐列表多样性不足，重新召回并增加多样性约束。

36.2.3 推荐工具箱设计

Agent 推荐系统的工具箱设计是关键工程问题。核心工具包括：

召回工具集：向量召回（双塔模型）、图召回（PinSage）、多模态召回（CLIP）、搜索召回（ES/SQL）。

排序工具集：精排模型（DNN/DIN）、多目标排序（MMoE/PLE）、多样性排序（DPP）。

知识工具集：知识图谱查询、属性查询、关系推理。

生成工具集：推荐理由生成（LLM）、搭配建议生成（LLM）、评论摘要生成（LLM）。

评估工具集：推荐质量评估、多样性检查、相关性检查。

工具箱设计需要平衡覆盖度和效率——工具太少无法覆盖复杂需求，工具太多增加 Agent 的决策难度和延迟。

36.3 RAG 检索增强推荐

36.3.1 RAG 在推荐中的意义

检索增强生成（Retrieval-Augmented Generation, RAG）是 LLM Agent 的核心技术之一。在推荐场景中，RAG 的意义是：从推荐系统的知识库中检索相关信息，增强 LLM 的推荐推理能力，同时减少幻觉。

推荐 RAG 的核心流程：

（1）索引构建：将物品库（物品描述、属性、评论）和用户画像构建为可检索的向量索引。

（2）查询生成：LLM 根据用户对话生成检索查询——如果用户说"想要夏季穿搭"，LLM 生成查询"夏季 连衣裙 短裤 凉鞋"。

（3）检索：从物品库中检索 Top-K 相关物品。

（4）增强生成：将检索结果作为上下文输入 LLM，生成推荐结果和推荐理由。

（5）验证：确保推荐结果对应真实物品（grounding），避免幻觉。

36.3.2 知识检索增强

除了物品检索，RAG 还可以检索推荐知识：

物品知识检索：检索物品的详细属性、适用场景、搭配建议。例如，检索"登山鞋"的知识——适用场景=户外徒步、材质=防水皮革、搭配=冲锋裤+速干衣。

用户画像检索：检索用户的历史偏好和行为模式。例如，检索用户过去一个月的浏览和购买记录，作为推荐上下文。

评论知识检索：检索物品的用户评论摘要，辅助推荐决策。例如，检索某商品的好评和差评关键词，帮助 LLM 生成更客观的推荐理由。

趋势知识检索：检索当前热门趋势和流行元素。例如，检索"2025 夏季流行色"或"当前热门穿搭风格"，使推荐紧跟趋势。

36.3.3 幻觉抑制

LLM 的幻觉问题在推荐场景中尤其危险——推荐不存在的物品或编造物品属性会严重损害用户信任。RAG 是抑制幻觉的核心手段：

Grounding：所有推荐结果必须对应检索到的真实物品。LLM 只能从检索结果中选择和排序，不能凭空生成物品。

属性验证：LLM 生成的物品描述需要与知识库中的实际属性对照。例如，LLM 说"这款鞋是皮面"，需要验证知识库中该鞋的材质确实是皮面。

引用溯源：推荐理由需要引用来源——"根据 500+ 用户评价，这款鞋的舒适度评分 4.8/5"。引用可以追溯到原始评论数据。

36.4 对话推荐系统

36.4.1 多轮对话推荐

对话推荐系统（Conversational Recommender System, CRS）通过多轮自然语言对话理解用户需求并推荐物品。与传统推荐系统的一次性推荐不同，CRS 可以通过对话逐步澄清用户需求、修正偏好、解释推荐。

典型对话流程：

用户："我想买件外套。"

Agent："好的，请问是日常穿着还是特殊场合？偏好什么风格？"

用户："上班穿，偏正式一点。"

Agent："了解。您偏好什么颜色和价位？"

用户："深色系，1000 以内。"

Agent：[调用推荐工具] "为您推荐三款：① XX 西装外套（深蓝，¥899）——修身剪裁，适合商务场合；② YY 风衣（黑色，¥750）——经典款式，百搭实用；③ ZZ 西装外套（深灰，¥950）——意大利面料，质感出众。您更倾向哪款？"

用户："第一款有别的颜色吗？"

Agent：[调用知识查询] "有的，还有黑色和灰色可选。"

这种多轮对话使推荐更精准、更透明。

36.4.2 意图理解与偏好修正

意图识别：Agent 需要识别用户对话中的推荐意图。用户说"最近有什么好看的电影"是推荐意图，"这个电影好不好看"是评价意图，"帮我查一下订单"是服务意图。意图识别准确率直接影响推荐体验。

偏好修正：用户在对话中可能修正之前的偏好——"其实我不要太正式的，休闲一点也行"。Agent 需要实时更新用户偏好表示并调整推荐策略。这要求 Agent 具备动态记忆和策略调整能力。

隐式偏好挖掘：用户可能不会直接说出所有偏好，Agent 需要从对话中挖掘隐式偏好。例如，用户说"不要太花哨"，Agent 推断用户偏好简约风格。

36.4.3 推荐解释生成

对话推荐的优势之一是可以自然地生成推荐解释。好的推荐解释应该包括：

用户需求回溯："您提到需要面试穿搭..."

物品匹配理由："这款西装采用修身剪裁，深蓝色沉稳大方，非常适合面试场景。"

差异化说明："相比您看过的其他款式，这款的面料更好，性价比更高。"

社会证明："这款在面试场景的推荐中好评率 95%。"

LLM 生成的推荐解释需要满足准确性（不编造信息）、相关性（与用户需求匹配）、多样性（不同物品的解释有差异）和自然性（语言流畅自然）四个要求。

36.5 多 Agent 推荐系统

36.5.1 角色分工的多 Agent

复杂推荐场景可以由多个专职 Agent 协作完成，每个 Agent 负责不同方面：

需求理解 Agent：负责与用户对话，理解需求和偏好。输出结构化的用户需求描述。

召回 Agent：根据需求描述调用多种召回策略，生成候选集。

排序 Agent：对候选集进行精排，考虑多目标平衡。

多样性 Agent：检查推荐列表的多样性，避免同质化。

解释 Agent：为推荐结果生成自然语言解释。

质量 Agent：评估推荐列表的整体质量，决定是否需要重新推荐。

多 Agent 协作的优势是专业化分工——每个 Agent 专注于自己的领域，整体效果优于单 Agent。劣势是协调成本高、延迟大。

36.5.2 辩论式推荐

多 Agent 辩论推荐是一种创新范式——多个 Agent 分别为不同候选物品"辩护"，通过辩论选出最优推荐：

Agent A："推荐物品 X，因为用户最近浏览了类似风格的产品，X 的评分最高。"

Agent B："推荐物品 Y，因为 Y 更符合用户当前的季节需求，且价格更优。"

Agent C（裁判）："综合考量，Y 的季节匹配度和价格优势更突出，推荐 Y。"

辩论式推荐通过多视角讨论避免单一视角的偏差，提升推荐全面性。但延迟较高，适合高价值决策场景（如旅游推荐、大额消费）。

36.5.3 Agent 间通信协议

多 Agent 推荐系统需要设计高效的 Agent 间通信协议：

消息格式：结构化 JSON 消息，包含发送者、接收者、消息类型、内容。

通信模式：同步（请求-响应）或异步（消息队列）。

冲突解决：当多个 Agent 给出矛盾推荐时，通过优先级或投票机制解决。

上下文共享：所有 Agent 共享用户对话上下文和推荐历史，避免信息孤岛。

36.6 工业实践与挑战

36.6.1 部署架构

Agent 推荐系统的工业部署架构通常包括：

LLM 服务层：部署大语言模型（如 Qwen、LLaMA）用于推理和生成。通常使用 vLLM 或 TensorRT-LLM 加速推理。

Agent 编排层：管理 Agent 的规划、工具调用和结果整合。可以使用 LangChain、AutoGen 等框架。

推荐工具层：传统推荐模型作为工具服务，通过 API 供 Agent 调用。包括召回服务、排序服务、知识查询服务。

对话管理层：维护对话状态、上下文和历史。支持多轮对话的连贯性。

缓存层：缓存常用查询结果和 LLM 输出，降低延迟和成本。

36.6.2 延迟优化

Agent 推荐的延迟是工业部署的核心挑战。一次推荐可能涉及多轮 LLM 推理 + 多次工具调用，总延迟可能达到数秒。优化策略包括：

流式输出：LLM 输出流式化，用户看到逐步生成的推荐结果而非等待全部完成。

并行工具调用：独立的工具调用并行执行，减少串行等待。

缓存复用：相似查询的 LLM 输出和工具结果缓存复用。

模型蒸馏：将 LLM Agent 的行为蒸馏为小模型，用于常见场景的快速推理。

分级服务：简单需求用小模型快速响应，复杂需求用完整 Agent 链路。

预计算：对热门场景预计算推荐结果，用户请求时直接返回。

36.6.3 效果评估

Agent 推荐的效果评估需要新指标体系：

推荐准确率：传统 CTR/CVR 指标仍然重要。

对话质量：对话轮次数、需求澄清效率、用户满意度。

推荐解释质量：准确性、相关性、多样性、自然度。可以使用 LLM 自动评估 + 人工评估。

用户参与度：对话深度、回访率、推荐接受率。

效率指标：平均推理延迟、工具调用次数、成本。

36.6.4 当前挑战

延迟与体验的平衡：多轮推理的延迟可能影响用户体验，尤其在对延迟敏感的信息流推荐场景。Agent 推荐更适合对延迟不敏感的高价值场景（如旅游、大额消费、B2B 推荐）。

成本控制：LLM 推理成本高，大规模部署需要精细化的成本控制策略。

安全与合规：Agent 的自主决策可能产生不可预测的推荐结果，需要安全护栏和合规审查。

与传统系统的融合：Agent 推荐不是替代传统推荐系统，而是补充。如何将 Agent 推荐与传统推荐系统有机融合是工程挑战。

用户接受度：用户是否愿意与推荐系统对话？这取决于场景和用户群体。年轻用户和复杂需求场景更适合 Agent 推荐。

36.7 本章小结

LLM Agent 推荐代表了推荐系统从"被动响应"到"主动交互"的范式转变。本章介绍了 Agent 推荐的核心组件——感知、规划、记忆、工具、执行、反思，以及 Function Calling、RAG、对话推荐、多 Agent 协作等关键技术。

Agent 推荐的优势在于：通过多轮对话深入理解用户需求、调用多种工具实现复杂推荐、生成自然语言推荐解释、根据用户反馈实时调整策略。这些能力使 Agent 推荐在复杂需求和高价值决策场景中具有独特价值。

然而，Agent 推荐也面临延迟、成本、安全等挑战。当前阶段，Agent 推荐更适合作为传统推荐系统的补充，在对延迟不敏感的高价值场景中优先落地。随着 LLM 推理成本的持续下降和 Agent 框架的成熟，Agent 推荐有望逐步扩展到更多场景。

展望未来，Agent 推荐的发展趋势包括：多模态 Agent（理解图片/视频输入）、主动式 Agent（在用户未提出需求时主动推荐）、群体智能 Agent（多 Agent 协作为用户服务）、个性化 Agent（每个用户有专属 Agent 持续学习其偏好）。Agent 推荐代表了推荐系统的下一个范式——从"推荐引擎"到"推荐助手"的转变。
