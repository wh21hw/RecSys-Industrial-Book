RL 流量调控

推荐系统不仅需要推荐用户感兴趣的物品，还需要调控流量分配以实现全局最优。流量调控涉及冷启动扶持、新品扶持、长尾挖掘、生态平衡等目标，这些问题本质上是在不确定环境下的序贯决策问题，与强化学习（RL）的框架天然契合。本章将系统介绍强化学习在推荐系统流量调控中的应用。

29.1 流量调控问题

29.1.1 冷启动扶持

新物品缺乏交互数据，传统推荐模型难以准确预估其 CTR/CVR。如果不主动扶持，新物品将长期得不到曝光，形成"富者愈富"的马太效应。流量调控需要将部分流量分配给新物品，通过探索收集数据，同时控制探索成本。

这是经典的探索-利用（Exploration-Exploitation, E&E）权衡问题：利用已知信息推荐高 CTR 物品（exploitation），还是探索新物品以获取数据（exploration）。强化学习的多臂老虎机框架是解决 E&E 问题的经典方法。

29.1.2 长尾挖掘

推荐系统的流量分布通常呈长尾分布——头部物品获得大部分流量，尾部物品获得很少流量。然而，尾部物品的总量远大于头部，挖掘长尾可以提升用户满意度和平台多样性。

长尾挖掘需要在保证整体效果的前提下，将部分流量分配给长尾物品。挑战在于长尾物品的数据稀少，难以准确预估效果。RL 方法可以在不确定环境下做出最优分配决策。

29.1.3 生态平衡

推荐系统需要维护内容生态的健康——不同类目、不同创作者、不同质量等级的内容需要获得合理的流量分配。纯 CTR 优化可能导致某些类目（如娱乐）占据过多流量，而其他类目（如知识）被边缘化。

生态平衡可以建模为多目标优化问题，也可以建模为约束优化问题——在 CTR 优化的约束下保证各类目的最低流量。RL 方法可以在长期视角下优化生态目标。

29.1.4 全局最优

传统推荐系统优化单次请求的 CTR，但单次最优不等于全局最优。例如，连续推荐相似内容可能导致用户疲劳，降低长期留存。RL 的优势在于可以优化长期累积奖励，而非单次奖励。

将推荐建模为 MDP（马尔可夫决策过程），状态是用户兴趣，动作是推荐物品，奖励是用户反馈，目标是最大化长期累积奖励。这种建模方式天然适合 RL 求解。

29.2.1 问题定义

29.2.2 ε-greedy

最简单的 E&E 策略：以 ε 概率随机探索，以 1-ε 概率利用当前最优臂。ε 是探索率，通常设为 0.05-0.1。

优势：简单易实现。

局限：探索是均匀随机的，不区分探索价值。对于明显差的臂仍然探索，浪费流量。ε 固定不随时间衰减，后期探索过多。

改进：ε 随时间衰减（ε = 1/√t），早期多探索，后期多利用。

29.3 上下文老虎机

29.3.1 上下文建模

上下文老虎机（Contextual Bandit）在 MAB 基础上引入上下文信息——每轮可以观测到用户和物品的特征。推荐系统天然是上下文老虎机问题：每轮请求可以观测到用户特征（上下文），需要从候选物品（臂）中选择推荐。

上下文特征：用户特征（性别/年龄/兴趣）+ 物品特征（类目/价格/统计特征）+ 上下文特征（时间/场景）。

奖励建模：奖励可以是点击（二值）、停留时长（连续）、购买金额（连续）等。不同奖励类型需要不同的建模方式。

29.3.2 线性模型

线性模型是上下文老虎机的基础：

  • LinUCB：线性奖励 + UCB 探索
  • Bayesian LinUCB：线性奖励 + 贝叶斯后验 + TS 探索
  • Linear TS：线性奖励 + Thompson Sampling

线性模型的优势是计算高效、可解释性强。局限是无法建模特征间的非线性关系。

29.3.3 神经网络模型

神经网络可以建模复杂的非线性奖励函数：

NeuralUCB：使用神经网络建模奖励，使用网络输出的不确定性进行探索。不确定性估计通过网络 ensemble 或 MC Dropout 实现。

Neural Thompson：使用神经网络建模奖励，使用贝叶斯神经网络的后验进行 Thompson Sampling。

挑战：神经网络的不确定性估计计算开销大。在线更新神经网络的参数需要特殊设计（如使用低秩近似降低计算量）。

29.4 马尔可夫决策过程建模

29.4.1 MDP 建模

将推荐系统建模为 MDP：

状态 S：用户兴趣状态。可以是用户最近 N 次行为的物品序列，或用户兴趣 embedding。

动作 A：推荐的物品或物品列表。动作空间可能很大（百万级物品），需要参数化动作空间。

奖励 R：用户反馈。可以是即时奖励（点击/购买）或延迟奖励（留存/GMV）。

转移 P：用户兴趣状态转移。推荐物品后用户兴趣如何变化。转移通常是未知的，需要从数据中学习。

目标：最大化累积折扣奖励 E[Σ γᵗ · rₜ]。

29.4.2 值函数方法

DQN：使用神经网络近似 Q(s, a)。通过经验回放和目标网络稳定训练。挑战：动作空间大，Q 值估计困难。

Deep Q-Network for Rec：将推荐物品的 Q 值建模为用户状态和物品 embedding 的内积。通过负采样减少计算量。

29.4.3 策略梯度方法

REINFORCE：直接优化策略 π(a|s) 的期望奖励。策略梯度 ∇J = E[∇log π(a|s) · (R - b)]。基线 b 减少方差。

Actor-Critic：Actor 学习策略，Critic 评估值函数。比 REINFORCE 方差更小。

工业应用：Meta 使用 REINFORCE 优化 Instagram 视频推荐的长期价值。阿里使用 Actor-Critic 优化淘宝推荐的长期留存。

29.4.4 离线 RL

在线 RL 需要与用户实时交互，风险高、成本大。离线 RL 从历史日志中学习策略，不需要在线交互：

BCQ（Batch-Constrained Q-Learning）：只从历史数据中学习的 Q-learning 变体。约束动作在历史数据中出现过的范围内，避免外推误差。

CQL（Conservative Q-Learning）：保守地估计 Q 值，对历史数据中未见的动作降低 Q 值估计。防止过度乐观的值估计。

工业应用：离线 RL 在推荐系统中的应用越来越受关注。阿里在 2023 年发表了多篇离线 RL 推荐论文，使用 CQL 从历史日志中学习推荐策略。

29.5 工业实践

29.5.1 阿里流量调控

阿里在淘宝推荐中使用 RL 进行流量调控：

冷启动扶持：使用 LinUCB 对新物品进行探索性曝光。根据物品特征（类目/价格/质量）估计 CTR 置信区间，在保证整体效果的前提下分配探索流量。

长期价值优化：使用 Actor-Critic 优化用户长期留存。状态是用户兴趣序列，动作是推荐物品，奖励是用户活跃度。

生态平衡：使用约束 MDP 保证各类目的最低流量分配。在 CTR 优化的约束下最大化长期 GMV。

29.5.2 腾讯广告流量调控

腾讯在广告推荐中使用 RL 进行流量分配：

广告冷启动：使用 Thompson Sampling 对新广告进行探索。根据广告特征估计 CTR 后验分布，在 eCPM 排序中加入探索项。

预算控制：使用 PID 控制器 + RL 调整广告出价，保证广告预算平滑消耗。RL 学习预算消耗的最优策略。

29.5.3 百度信息流调控

百度在信息流推荐中使用 RL 进行内容生态调控：

内容多样性：使用 MDP 建模用户浏览过程，优化长期多样性。避免连续推荐相似内容导致用户疲劳。

创作者扶持：使用 bandit 算法对新兴创作者进行流量扶持。根据创作者质量和内容特征分配探索流量。

29.6 本章小结

强化学习在推荐系统流量调控中扮演着重要角色。本章介绍了流量调控的核心问题（冷启动/长尾/生态/全局最优）、多臂老虎机算法（ε-greedy/UCB/LinUCB/Thompson Sampling）、上下文老虎机（线性/神经网络模型）、MDP 建模（值函数/策略梯度/离线 RL）和工业实践。

流量调控的核心是探索-利用权衡——在利用已知信息推荐高效果物品和探索新物品以获取数据之间取得平衡。bandit 算法适合短期 E&E，MDP 方法适合长期价值优化。

在实践中，RL 流量调控通常与传统推荐模型结合使用——传统模型负责效果推荐，RL 负责探索和长期优化。这种混合策略既保证了短期效果，又兼顾了长期价值。
